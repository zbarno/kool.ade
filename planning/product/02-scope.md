## 2. Scope

**Current scope.** Linux x86_64 desktop planning from source; git-backed modular product and feature specifications; repository inspection; authority-aware open items; scoped context; resumable task generation; repository-specific implementation worktrees; automatic integration where enabled; post-merge reconciliation; Kanban oversight; operator-local chat and checkpoints. The Pi harness remains the model boundary. F-16, F-17, and F-18 provide setup, ownership settings, and MCP configuration.

**Deferred.** The WebSocket collaboration channel is post-MVP (D-18, D-22; D-32 rules its topology, reach, and trust ground - direct instance-to-instance WebSockets, local-network first, peers qualified by repository access - and D-33 rules its writer model as true concurrent co-authoring; CLR-017 resolved by D-31). Alternate harnesses (D-12), packaged distribution (D-11; CLR-001 resolved), and the real-team pilot (D-20) are also deferred. F-19 and F-20 are accepted board-display changes whose implementation remains pending (D-26, D-27).

**Excluded.** Direct provider APIs, embedded inference, a separate authoritative knowledge database, mandatory semantic/vector indexing, cross-repository atomic publication, and autonomous implementation of an unapproved new feature. The operator's ownership model (D-14) is lightweight routing rather than a login/ACL service. Private chat remains operator-local by ruling (D-07, ratified by D-31).

The older single-file and no-fetch scope statements are superseded by D-28 and D-30. The binding MVP acceptance scenario remains D-20/D-21; CHG-001 has its own additive acceptance bar.
