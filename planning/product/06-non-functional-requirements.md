## 6. Non-Functional Requirements

- **NFR-1 Storage discipline:** git is the sole durable store for shared planning state; no database; operator-private state confined to `$PACKET_HOME` (Contract §2, §17). D-18 clarification: the prospective real-time collaboration channel (CLRs 015–017; phased post-MVP by D-22) is transient by mandate — presence, liveness, possibly streamed work — with git checkpoints remaining the reconciliation authority; nothing durable rides the wire, and no wire exists at all until after the MVP.
- **NFR-2 Atomicity:** all planning-file writes are write-to-temp-plus-rename; a crash mid-write cannot corrupt an artifact.
- **NFR-3 Consistency:** single-writer invariant (concurrent submits refused while a turn runs); the UI adopts the produced state only after apply lands. The invariant is per-process — today it is enforced at UI level only (second submit refused; `src/core/turn.rs`), with no cross-process guard — and the multi-client writer model is expressly undecided (D-18, CLR-016), now squarely post-MVP territory under D-22.
- **NFR-4 Responsiveness:** UI ticks are decoupled from the turn worker; hours-long turns are tolerable with live progress plus Cancel; default budget 12 h, RULED by D-24 (superseding D-08's original 2 h recording; CLR-018 resolved). Qualitative by ruling — no quantitative latency or throughput targets bind this requirement (D-19).
- **NFR-5 Security posture:** no built-in LLM or provider networking; model and MCP traffic belongs entirely to pi's external configuration (confirmed unaffected by the D-18 ruling on CLR-006); Packet's own network surface is nil at baseline and receives exactly one reservation — the D-18 collaboration channel — which must earn conservative scoping (trust, discovery, encryption) before it ships (CLR-015); that reservation is scheduled after the MVP by D-22, so the MVP itself ships with strictly zero Packet-initiated network surface; git invocations use argument arrays (no shell interpolation); imported filenames are sanitized; the app stores no credentials.
- **NFR-6 Extensibility:** the `AiHarness` trait isolates pi internals; alternate backends (Codex CLI, Copilot CLI, Claude Code, OpenCode) can plug in without planner-core redesign (Contract §15); their arrival is post-MVP intent (D-12). At MVP the operator provisions the harness CLI(s) manually per the setup guide (F-16, delivered in-app per D-15); in-app installation/provisioning automation is not owed.
- **NFR-7 Deployment target:** pure Rust (edition 2024); offline-capable dependency graph (`cargo run --offline`); thin-LTO release profile; minimal dependency set (egui/eframe 0.36.1, serde plus serde_json, chrono, pulldown-cmark, anyhow) — dependency graph audited for D-18: no socket or async crate present, so the collaboration channel, when admitted, forces the first departure from this posture; its admission is now timed to post-MVP by D-22, keeping the MVP fully offline/minimal, and the departure will still be treated as an explicit carve-out rather than quiet accretion. The deployment target is a single Linux x86_64 workstation operated by the operator themselves, built and run from source with a local toolchain (verified host: Linux x86_64, rustc 1.98.1; D-11 extended, CLR-001 resolved). Cross-platform/cross-arch builds, portable bundles, and any shipped artifact are explicitly out of MVP scope.
- **NFR-8 Quality bar:** warning-free build; test suite green at baseline (88/88 per the baseline commit); regressions pinned by tests (e.g., tri-state stream polling separating timeout from stream death, with stderr surfaced in error toasts). The owed D-14 routing-matrix, D-15 guide-render, and D-16 MCP save-path pins all LANDED with tickets 002–004 (v1.2 verified); the suite now totals 203 test functions on master (202 unit in `src`, 1 integration in `tests/`), and each landed pin rides inside it.
- **NFR-9 History readability:** checkpoint subjects are short imperative phrases; no per-message commit churn (Contract §20).
