# 001 — Refine task_activity graph into a reusable anchored red line chart painter

Feature: Board Card Display — Red-Line Activity Graph and Class-Colored Cards (CHG-002)

Status: Individually validated; see batch index for generation status.

## Problem this ticket solves and why

F-19 (D-26) needs a dependable line-chart primitive for the board card, but the only chart painter in the tree — task_activity::graph (src/ui/task_activity.rs:20) — computes its window end from an internal chrono::Utc::now() call whenever live=true, derives the settled anchor from the largest sample bucket instead of the record's timestamp, hardcodes theme::DANGER at a fixed 1.8 px stroke with fixed geometry, and mixes caption label, hover copy and 1-second repaint scheduling into the same function. Without decomposition the next ticket cannot mount a card line whose anchor reflects per-card activity state, and nobody has unit-proved the degenerate-telemtry obligations of REQ-F19-4 at the painter level; shipping on the current coupling would bake wall-clock nondeterminism and color coupling into the card and defeat the settled-window and DANGER-singularity rules.

## Ticket goal — what changes when done

After this ticket alone, src/ui/task_activity.rs exposes a pub primitive line_chart(ui, samples, anchor, color, size) -> Response whose window, normalization, baseline and degenerate behavior are pinned by in-file unit tests, and every pre-existing consumer (five layout.rs call sites) continues to render through a compatibility graph adapter with byte-identical appearance and hover copy, leaving layout.rs itself with zero hunks; the observable completion condition is the new tests passing under cargo test --offline with cargo clippy --all-targets --offline warning-free and no card mount yet claimed (that is story 2's territory, stated explicitly).

## User story

As the implementer landing CHG-002 F-19's board-card chart in the next ticket, I want a standalone pub line-chart painter in task_activity that takes samples, an explicit ten-second-tick window anchor, a line color and a size, so that I can mount a per-task activity line with card-state-derived anchors and my own caption without untangling embedded clock logic or a hardcoded DANGER stroke.

## Purpose

Frozen base 28ba698 diverges from the spec audit: task_activity::full has no accent bar subchart, but a rudimentary red line painter (task_activity::graph with its window helper) already exists, buries its window anchor behind a live flag, hardcodes line color and geometry, and is not exercised as the general-purpose primitive brief scope item 1 demands, so the card mount that follows has no dependable reusable component to rest on. Convert that painter into a pub primitive taking samples, a window anchor (ten-second tick via floor(epoch_ms/10_000)), a line color, and a size: reuse the established 60-slot bucket math (sixty-bucket window ending at the supplied anchor, peak normalization max(samples,1)), render the faint baseline, and guarantee degenerate safety (empty, all-zero, and pre-window telemetry all yield a flat line with no panic and no invented spikes); demote the existing consumers (layout.rs:108 main-chat All-activity strip and the item-details activity region) to a compatible adapter so their appearance does not shift, and lock the math with in-file unit tests (brief scope item 5, REQ-F19-1, REQ-F19-4). Sequenced behind the ticket-007 resume per P2, and F-19 lands before F-20.

## Technical design and contracts

- Add pub fn line_chart(ui: &mut egui::Ui, samples: &[(i64, u64)], anchor: i64, color: egui::Color32, size: egui::Vec2) -> egui::Response to src/ui/task_activity.rs: anchor is a ten-second tick (floor(epoch_ms/10_000)) denoting the window's RIGHT-most slot, so slot i covers bucket anchor-59+i via the existing pub fn window; the body computes values = window(samples, anchor), peak = values.iter().copied().max().unwrap_or(0).max(1), allocates (rect, response) = ui.allocate_exact_size(size, egui::Sense::hover()), plots in rect.shrink2(egui::vec2(2.0, 4.0)), strokes the 1.0 px theme::BORDER baseline segment [left_bottom, right_bottom], then pushes a 60-point Vec<egui::Pos2> with x = plot.left() + plot.width()*i as f32/59.0 and y = plot.bottom() - plot.height()*values[i] as f32/peak as f32 into ui.painter().add(egui::Shape::line(points, egui::Stroke::new(1.8, color))), and returns response; the primitive performs NO clock reads, NO request_repaint, NO label or hover text, and skips emitting shapes when plot.width() <= 0.0 || plot.height() <= 0.0.
- Rewrite the existing pub fn graph(ui: &mut egui::Ui, samples: &[(i64, u64)], live: bool, height: f32) in place as a thin compatibility adapter over line_chart, keeping its exact signature so all five layout.rs call sites (:108, :501, :527, :628, :916) compile and render unchanged: resolve anchor exactly as today (now = chrono::Utc::now().timestamp_millis()/10_000; anchor = now if live else samples.iter().map(|(b,_)| *b).max().unwrap_or(now)), call line_chart(ui, samples, anchor, theme::DANGER, egui::vec2(ui.available_width(), height)), re-derive peak = window(samples, anchor) then .max(1) solely to interpolate the VERBATIM legacy hover string attached via response.on_hover_text(...), keep the live-only ui.ctx().request_repaint_after(std::time::Duration::from_secs(1)), and keep printing the existing small/weak label ('No activity yet' | 'Live activity' | 'Last recorded activity'); the legacy 'peak {peak}/10s' phrasing (which prints 1 for an all-zero window) is a known cosmetic quirk retained verbatim for appearance stability, not corrected.
- Keep the module's existing exports intact — window, graph, preview, timing, compact, full — add no re-exports and change no other module; specifically leave task_activity::full, task_activity::compact, layout.rs and theme.rs semantically untouched (theme.rs's incorrect board_hue table is owned by story 3), because story 2 will call line_chart directly from the board task-card closure with anchor = floor(current_ms/60_000)*6 for active cards and floor(progress.telemetry.updated_ms/10_000)-style record anchors for settled cards, and story 2's repaint cadence belongs to that mount, not to the primitive.
- Extend the in-file #[cfg(test)] mod tests with a shared capture helper fn line_points(shapes: &[egui::Clipped]) -> Option<&[egui::Pos2]> that finds the first egui::Shape::Path with exactly 60 points, plus focused tests: (a) window slot alignment, duplicate-bucket summation and zero-row contributions; (b) degenerate rendering — empty samples, all-zero rows, samples strictly before the window, and samples strictly after the anchor each yield exactly one flat 60-point Path sitting on the plot's bottom edge plus the baseline LineSegment, with no panic; (c) peak normalization placing the argmax vertex at the plot top only when that bucket uniquely dominates; (d) anchor determinism — identical inputs in two fresh egui::Context::default().run_ui passes produce element-wise-equal point sets (proving no clock leak), and anchor+1 shifts the profile one slot; (e) the color argument controls the polyline's solid stroke color (assert PURPLE vs DANGER distinctly).

## Edge cases and failure handling

- Trigger: extremely narrow allocation (the :108 header strip wraps graph in a .max(40.0) width floor that can still degrade under window resize). Required behavior: points compress uniformly across however many pixels exist thanks to the width·i/59.0 formula, and the primitive suppresses drawing when the shrunken plot collapses to zero size; invariant: no negative dimensions, division-by-zero or inverted geometry at any allocation.
- Trigger: duplicate (bucket, count) rows reaching window — possible in principle even though Surface::activity_samples in src/app/root.rs already BTreeMap-merges and LiveProgress::update coalesces same-tick increments. Required behavior: window keeps saturating_add so slot value equals the summed observed updates; invariant: monotonically capped accumulation, silently safe at u64::MAX, with totals asserted in the new window-math test.
- Trigger: a settled record whose newest sample precedes the window's left edge (anchor chosen from telemetry.updated_ms far past the last burst, per story 2's settled-card rule). Required behavior: all 60 slots zero → flat baseline, never extrapolated or shifted activity; invariant: rendered occupancy exactly equals samples ∩ [anchor-59, anchor], and the degenerate test family locks this.
- Trigger: an all-zero row set inside the window (rows with count 0, or live window before first update). Required behavior: the max(peak, 1) floor forces a divisor of 1 so no division-by-zero or NaN arises and the adapter's legacy copy keeps printing 'peak 1/10s' verbatim; invariant: numeric safety plus deliberate deferral of the cosmetic wording fix to story 2's card caption rather than silently altering incumbent chrome.
