# 002 — Enforce the D-14 sole, group, and seat routing law in item evaluation and envelope validation

Feature: Packet MVP — git-native desktop specification planner

Status: Individually validated; see batch index for generation status.

## Problem this ticket solves and why

Verified in src/core/routing.rs: evaluate(item, user) never receives the stakeholder configuration, so the D-14 law is unenforced on two fronts at once. First, every unassigned non-General item returns NotEligible for everyone (the dead tail branch), so the chair's seat-inherited lane questions can never be posed, stalling Section 12 checklist legs (b) through (d). Second, src/core/validation.rs line 220 treats an ineligible next_question_id as a soft warning and drops only that field, so an envelope that misroutes a question still applies its spec and item mutations - violating FR-6 (ineligible selections are rejected at validation) and making the Section 12(f) zero-mutation leg unreachable. Left unresolved, the single-actor exit demonstration fails and model-emitted misroutes would silently mutate the living specification.

## Ticket goal — what changes when done

Before: routing decides solely on name-address, group-address, and General; config owners are invisible; a misrouted next_question_id costs a warning while the rest of the envelope mutates state. After this ticket alone: evaluate(item, user, stakeholders) enforces the four-rule law (General broadcast; direct name or group address; the category explicitly owned by the user, sole or via group membership; unowned categories inheritable only by the seated non-guest operator), the other-holder veto outranks direct address, and any routing violation in an envelope is a FATAL validation problem so the whole turn is Rejected with zero artifact writes and zero commits; the prompt teaches the law plus a per-seat lane digest, and the items pane partitions FOR YOU NOW under the same law. Observable completion: cargo test --offline is green including the rewritten regression matrix, the fatal-misroute pin, and a turn-level hash-pinning zero-mutation test; a live misrouted envelope surfaces as Rejected with prior artifacts byte-identical.

## User story

As the git-seated chair operating Packet, I want item eligibility decided by the D-14 law so that only questions my seat lawfully holds reach me - General broadcasts, items addressed to me or my groups, lanes I solely or share-own, and unowned lanes I inherit - and I want any agent attempt to serve another person's sole-owned lane, or to violate routing at all, to reject the entire turn without touching a single artifact, so that eligibility is enforced by the application and legible in git history rather than delegated to model goodwill.

## Purpose

core/routing.rs::evaluate still takes only (item, user) and declines every unassigned non-General item for everyone, so the chair's inherited lane-bound questions can never be posed and the agent's next_question_id choice escapes the D-14 law. With validation not enforcing the law, FR-6 is unenforceable and misrouted envelopes would mutate state, so this ticket lands the four-rule law in the evaluator, in envelope validation with zero mutation on rejection, in the prompt text, and as regression-matrix pins.

## Technical design and contracts

- src/core/routing.rs - replace the two-arg evaluator with pub fn evaluate(item: &OpenItem, user: &CurrentUser, stakes: &Stakeholders) -> Eligibility, backed by a private enum LaneClaim {Unowned, SoleMine, SharedMine, ClaimedByOthers} and classifier fn lane_claim(category, user, stakes): Unowned iff stakes.find(category) is None or the entry's member list is empty; SoleMine iff any member, trimmed and case-folded, equals user.name; SharedMine (only when no name hit) iff any member matches one of user.groups; else ClaimedByOthers. Verdict order is fixed: (1) is_general_category gives Eligibility::General; (2) ClaimedByOthers gives NotEligible BEFORE the address axis, realizing Section 8's never-posed veto even against direct address; (3) otherwise user.matches_assignment(assigned_to) yields ByName/ByGroup when Somebody; (4) when Nobody addressed: SoleMine gives new variant Eligibility::SoleOwner, SharedMine gives Eligibility::SharedOwner, Unowned gives Eligibility::SeatInherited only when user.name differs from GUEST_NAME, else NotEligible. eligible_items and recommended_next gain the stakes parameter; the (priority.rank(), id) selection key, ownership-item exclusion, and is_eligible() (extended true for the three new variants) are otherwise unchanged. Module doc restates the four rules verbatim and deletes the obsolete tail-branch comment.
- src/domain/user.rs - add pub const GUEST_NAME: &str = (guest) next to GENERAL_CATEGORY; refactor the literal in src/core/state.rs to use it (coordinating with dependency ticket 1 if its composer duplicated the literal), keeping guest fabrication byte-identical. Rewrite the CurrentUser doc comment, which currently quotes the retired three-rule summary, to the four-rule law so documentation stops citing the dead formulation.
- src/core/validation.rs - in validate_for_turn, the next-question arm currently matching Eligibility::NotEligible into warnings.push(dropped) becomes a FATAL: push a problem naming the item id, its category, its assignee, the seated user's name, and the phrase violates the routing law, letting it flow into the existing fatals guard (non-empty fatals return Err, which run_turn maps to TurnOutcome::Rejected - the existing mechanism guaranteeing zero artifact writes and zero commits, so no pipeline change is needed for zero mutation). The unknown-id, resolved-this-turn, and ownership-kind arms remain non-fatal warnings (noise, not law violations). The law applies uniformly to both TurnPurpose values: a task-generation envelope naming an ineligible next_question_id is rejected exactly like an interview turn (practice is for story envelopes to omit it).
- src/core/prompt.rs - rewrite the SYSTEM_INSTRUCTIONS block headed ROUTING (enforced by the app, mirrored here for coherence) to state the four rules the evaluator enforces: (a) category General reaches everyone; (b) assigned_to names the user directly or one of the user's groups; (c) the category is explicitly configured to that user, sole person or member group; (d) the category has no explicit owner and the user is the seated git-identified operator (seat inheritance) - plus the veto (lanes claimed by other holders are never askable of this user, even when addressed by name) and the consequence sentence Choosing a next_question_id that violates these rules REJECTS THE ENTIRE TURN - nothing is saved. Golden-text pins per NFR-8.
- Per-seat lane digest - add pub fn describe_lanes(user: &CurrentUser, stakes: &Stakeholders) -> String in routing.rs producing a stable 0-3 line digest in config order: line Sole-owned lanes with the categories, line Shared lanes with the via group qualifier, line Seat-inherited unowned lanes with the categories the user answers from their seat; empty string for an empty config or for the GUEST_NAME seat, which inherits nothing. Wire it by adding pub lane_note: String to context_build::TurnContext, populated in TurnContext::build via describe_lanes(&state.effective_user(), &state.config.stakeholders), rendered by prompt.rs inside the CURRENT USER section only when non-empty - so the harness sees exactly which ids it may legally propose for THIS seat.
- UI plumbing - ui::items_pane::Args gains pub stakes: &'a Stakeholders and paint passes it to both routing calls, so partition semantics change automatically: unowned-lane items move into FOR YOU NOW for a non-guest; claimed-other lanes stay in the remainder of the queue, visible but never ASKING NOW. The Surface trait in src/ui.rs gains fn stakeholders(&self) -> &Stakeholders;, implemented at root.rs line 328 (connected project derefs to &state.config.stakeholders; welcome screen returns a static empty Stakeholders default) and forwarded at layout.rs line 89. No new pane visuals are owed - the badges and sections already exist.

## Edge cases and failure handling

- Mixed owner list (members Morgan and QA Guild): Morgan classifies SoleMine because the name match takes precedence, any QA Guild member classifies SharedMine, every other operator classifies ClaimedByOthers - the person-versus-group distinction emerges from per-user membership testing per the stakeholder doc (semantic, not syntactic), needing no global registry.
- Seeded-repo trap: bootstrap_missing seeds the default categories as entries with EMPTY member lists, so entry-exists-but-members-empty must behave identically to no-entry (Unowned, seat-inheritable) - otherwise a brand-new repository's chair could never be asked any seeded lane; ownership synthesis keeps emitting its Ownership items independently, since the law governs poseability while synthesis governs paper coverage.
- Spelling drift: category infosec in config versus InfoSec with a trailing space on the item must classify identically (fold via the same trim-plus-casefold stance Stakeholders::find already uses), owner ZACH with padding still SoleMiness user Zach, and assigned_to matching inherits matches_assignment's existing tolerance.
- Guest degradation: the (guest) seat keeps General and direct name/group address (the legacy experience is a strict subset of the new law) but never inherits unowned lanes, preserving the Section 9 degraded-but-functional, never-blocked contract for trees with no git identity and no config block.
- Same-turn workflow interplay: workflow readiness handling nulls next_question_id only AFTER successful validation; the routing fatal fires before that step, so a misrouted envelope arriving together with a readiness exchange is rejected wholesale with zero mutation rather than silently downgraded - the validation ordering is the invariant that protects FR-4.
- In-flight immutability: the verdict is computed from the immutable TurnInputs state snapshot, so an external .planner/config.md edit or a settings-Save (already refused mid-turn by the single-writer UI guard) cannot shift eligibility mid-turn, and cooperative cancel bypasses apply entirely - the law introduces no mutable intermediate that cancellation could strand.

## Rollout and compatibility

Artifact-compatible throughout: no envelope schema, config format, or persistence change - only adjudication and its messaging shift, and both shifts ARE the D-14 ruling made operative. Behavioral widenings (unowned lanes wake the seated operator; direct address into a sole-owned lane loses) are the intended law, and the Section 11 risk note anticipated exactly this widening demanding that validator and regression matrix land together (this ticket lands both). One tightening is operator-visible: envelopes that previously survived as warnings-with-mutation are now wholly rejected and trivially retried, which is what the Section 12(f) demonstration requires. The two-arg evaluate has only intra-crate consumers (grep-verified: validation.rs, items_pane.rs, tests), so no compatibility shim is owed. Rollback is reverting this one change set with no on-disk residue because no new artifact shapes exist. Sequencing: requires dependency ticket 1 (without a real non-guest seat, rule (d) fires for nobody) and unblocks the demonstration's lane-bound checklist legs plus the ticket-6 certification.
