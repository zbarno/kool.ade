# 003 — Write the unlabeled reply-tail digest contract as two prose-only paragraphs in prompt.rs and turn.rs

Feature: Readable Chat Replies with At-a-Glance Asks and Quick Option Chips (CHG-003)

Status: Individually validated; see batch index for generation status.

## Problem this ticket solves and why

Stories 1, 2, 4 and 5 of this batch all DETECT, RENDER, or CHIP a reply-tail digest, but nothing in the planner's standing instructions tells the model to EMIT one: at base d881038 the only reply-tail grammar anywhere is the card-mode line at src/core/turn.rs:255 ("end with a separate line beginning exactly 'Your next step:'..."), and Main Chat has no tail convention at all. Left unresolved, the shared detector from story 2 is dead code on fresh turns, Main Chat would lift blocks that never arrive, and the whole CHG-003 surface ships dark. The fix must be prose-only because the final fenced JSON envelope is the sole machine contract: any logic, constant, or semantics drift in the prompt pipeline risks breaking extraction, routing validation, or interview/generation modes, so the change is exactly two paragraphs plus in-file invariant tests.

## Ticket goal — what changes when done

Before: every turn's system instructions either teach the fragile 'Your next step:' line (task mode only) or teach nothing (main chat), and no test ties any tail prose to envelope extraction. After this ticket alone: every turn mode's system_instructions carries the unlabeled digest emission contract (main chat and investigations via SYSTEM_INSTRUCTIONS; task conversations via the generalized turn.rs paragraph), the legacy 'Your next step:' emission ORDER is provably retired (asserted absent), and a triple invariant test proves pi_extract::extract_json_object and turn.rs decode_envelope return the envelope BYTE-IDENTICALLY for a reply with a well-formed digest versus the same reply minus its digest — including an adversarial draft-fence case. Observable: the three new in-file tests plus pin tests pass, the full offline suite and warning-free clippy are green, and the diff touches only src/core/prompt.rs and src/core/turn.rs. Rendering lift (story 4) and chips (story 5) are downstream and NOT claimed by this ticket.

## User story

As the seated operator (Zachary Barno, sole operator per D-23) reading planner replies in Main Chat and per-card conversations, I want every planner reply that awaits my input to end with the same unlabeled digest — one '---' line, at most five bullets ordered ask → recommendation → pointer, discrete choices each given their own repeatable bullet — so that I can see at a glance what is wanted, what is recommended, and where to look, while freeform answers stay equally open and 'Nothing needed' replies carry no fake ask.

## Purpose

Until the planner's response contract instructs the model to emit the unlabeled digest, the new detector and lifted block wait on output that never arrives, yet any prompt drift could disturb extraction or oblige listable replies. This ticket adds exactly two prose-only prompt paragraphs — one in the main-chat RESPONSE CONTRACT (src/core/prompt.rs, line 67+ region) and one generalizing the task-mode convention (src/core/turn.rs, line ~264 region) — stating that replies awaiting input end with a '---' rule and ≤5 bullets ordered ask → recommendation → pointer (options listed as plain bullets when discrete choices exist), that 'No reply needed.' closesouts carry no digest, and that freeform replies remain always valid; no prompt logic, constant removals, or semantics change, and an invariant test proves pi_extract returns the envelope byte-identically for a digest-bearing reply versus the same reply minus its digest.

## Edge cases and failure handling

- Retirement asymmetry (emission vs parsing): the model is no longer ORDERED to emit 'Your next step:' lines, but the parser must never lose sight of them — stored card conversations containing the legacy line keep classifying as NextStep via the story-2 detector; a transitional reply carrying BOTH shapes lands as NextStep (legacy outranks Digest, locked by story 2), so no stored reply changes meaning from this ticket alone.
- Passive consumer fan-out: investigation.rs:126 composes SYSTEM_INSTRUCTIONS + SPECIFICATION_POLICY for autonomous item probes whose prompt says 'Do not ask the user', so the digest paragraph is present but dormant there; interview/generation turns share SYSTEM_INSTRUCTIONS and the interview mode explicitly summarizes rather than asks, keeping the digest untriggered; no consumer gains a new rejection path because validation.rs is untouched (assistant_message only needs to stay non-empty).
- Concidence collision: the task-mode 'at most 60 words' cap, left unadjusted, would steer the model to truncate its own five-bullet tail; the carved phrase 'excluding any reply-tail digest' neutralizes that pull, while Main Chat's '~120 words' norm (OPERATING PRINCIPLES rule 2) is deliberately NOT touched — scope discipline, noted so a reviewer does not 'fix' it later inside this ticket's files.
- Encoding and literal hazards: the prose uses single quotes and em-dashes only (double quotes would need Rust escaping; em-dashes already appear in both files, proving UTF-8 hygiene), and every pinned needle must sit within one physical source line because backslash continuations glue lines with no separator — a careless re-wrap breaks the pin tests, which is exactly the protection intended.
- Streaming and malformed-output immunity: decode_envelope runs only on the complete final_text, so half-written digests during a live turn cannot poison extraction; if a model ever plants a stray ```json inside a bullet (violating 'standing on its own line'), last-fence-wins plus pair C's adversarial assertion demonstrate the envelope still extracts byte-identically.
