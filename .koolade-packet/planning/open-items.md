### Question
When a harness or provider reports no cost, should Kool.ad/e estimate from a vendor-independent, versioned per-model price table bundled with the app, render n/a for calls with no known price, and never recompute historical runs when the table or pricing changes?


### Reason
The issue requires displaying 'Estimated API cost' unless authoritative billing data exists, and requires historical estimated cost to remain stable under later pricing or configuration changes. A deterministic fallback prevents silent zero-cost reports while preserving run-level cost stability; the choice is reversible by swapping the estimator without touching stored records.


### Evidence
Issue #23 cost-semantics section (transcribed into F11 R6): report cost as estimated unless authoritative billing data exists; preserve the cost associated with the historical execution rather than recomputing old runs. No cost, token, or pricing fields appear in the inspected harness fold (src/harness/pi_events.rs EventFold: final text, activity, stop reason, error class, tool counts), so estimation cannot piggy-back on existing reported data today.
