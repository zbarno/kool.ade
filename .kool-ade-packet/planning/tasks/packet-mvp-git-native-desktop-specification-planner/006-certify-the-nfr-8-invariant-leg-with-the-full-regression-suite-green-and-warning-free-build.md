## Edge cases and failure handling

- Trigger: a timing-sensitive test (pi_proc's real-sleepper poller tests, or the probe simulation under heavy machine load) fails in run #1 and passes in run #2 — required behavior: the gate records the oscillation, re-runs that test's module three times in isolation, and classifies environmental-flake only if ALL three isolate runs pass and the failure correlates with load; otherwise it is Class-B and FAILS; invariant: 'two green full runs' stays the bar, and a skip/ignore is never the remedy.
- Trigger: the developer's ambient global git identity leaks into a supposed git-absent identity fixture — required behavior: the hermetic probes already redirect GIT_CONFIG_GLOBAL/SYSTEM under the chat_store-style process lock; if a new fixture nevertheless wobbles between machines, it is a Class-A scar fixed by adopting the same shadowing pattern, never by loosening the assertion; invariant: identity tests must seat identically on a git-naive CI box and this operator host.
- Trigger: incremental cache masking — a warning that only appears on cold compile, or a stale fingerprint hiding a recompile after a merge — required behavior: the touch protocol defeats fingerprint staleness for the bar; the supplemental cold cargo build --release --offline catches release-only warnings; if a warning appears ONLY under release, it still counts (NFR-8 names no profile exception); invariant: the transcript's zero-warning claim covers every unit the gate actually compiled.
- Trigger: a cross-ticket merge scar — e.g. ticket 1's identity composer and ticket 2's GUEST_NAME swap both touching state.rs/user.rs, or ticket 3's from_project fields landing on ticket 1's rewritten constructor — required behavior: static seams (step 1) plus dead_code warnings catch it pre-suite; the fix is the minimal edit consistent with the OWNING ticket's contract, followed by a full gate re-run from the warning step; invariant: no fix may alter behavior beyond the union of the four landing tickets.
- Trigger: the certified census disagrees with 112 + the four deltas (an extra helper test slipped in, or a ticket under-delivered its pins) — required behavior: the gate halts and prints the symmetric difference of baseline-versus-live rosters; the operator and owning ticket are named; reconciliation happens upstream, not by adjusting the expected arithmetic to fit; invariant: the number is evidence, and bending it is exactly the quiet drift D-21 exists to prevent.
- Trigger: leftover packet_* temp dirs in /tmp from interrupted earlier test runs (ticket 4's per-label pid-suffixed repos, gitops mkrepo leftovers) — required behavior: the gate ls /tmp before running and records stray dirs; tests self-clean on both success and failure paths, so strays are advisory noise, reported but not gating unless a suite failure correlates with them; invariant: a green run is claimed only on a clean slate, preventing cross-run contamination readings.
