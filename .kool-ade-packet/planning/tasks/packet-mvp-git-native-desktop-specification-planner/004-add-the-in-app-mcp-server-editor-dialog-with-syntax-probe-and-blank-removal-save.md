## Problem this ticket solves and why

There is no sanctioned in-app path to author .planner/mcp.json: the verified advertising mechanism (context_build.rs reads the raw file, prompt.rs re-emits it verbatim) is unreachable from any UI, so the operator must hand-edit a dotfile out of band — bypassing NFR-2's atomic write, producing uncheckpointed drift in git — or advertise no MCP servers at all, silently starving the pi session of the configuration it expects (D-16 ruled hand-edit-at-launch out). Leaving this unresolved defeats F-11 in everyday use and contradicts a binding decision.

## Ticket goal — what changes when done

Before: the header's Workspace menu offers only Import references, Stakeholders & ownership, Refresh, Disconnect; MCP configuration is invisible and uneditable. After: a new 'MCP servers' header entry opens a card preloaded with the live file bytes (or a valid-JSON exemplar hint when absent); Save atomically writes and checkpoints 'settings: update mcp server configuration'; a blank save removes the file and checkpoints 'settings: clear mcp server configuration'; malformed JSON saves anyway with a sticky inline warning. Observable completion: cargo test --offline green with the mcp_io pins, and on the connected repo one Save produces git-tracked .planner/mcp.json whose bytes equal the editor text, legible as a new checkpoint in git log.

## User story

As the solo operator planning against my own repositories, I want the header-launched 'MCP servers' card to edit .planner/mcp.json as raw mono-spaced JSON in place, saving it with an atomic write plus its own git checkpoint while a syntax-only probe warns — without blocking — on malformed input and while a blank save deletes the file to mean unconfigured, so that the pi session advertises exactly the servers I intend, every change is checkpoint-readable in git history, and I never fall back to hand-editing a dotfile by hand.

## Purpose

Until F-18 ships there is no sanctioned in-app path to author .planner/mcp.json: the operator either hand-edits out of band (bypassing NFR-2 atomicity and contradicting D-16's rule out of hand-edit-at-launch) or advertises no MCP servers to the pi session at all. This ticket delivers the header-launched editor with the syntax-only well-formedness probe, non-blocking malformed-input warning, blank-save removal to unconfigured, atomic write, and dedicated checkpoint.

- NEW module src/artifacts/mcp_io.rs registered in src/artifacts.rs (pub mod mcp_io; plus a layout-comment bullet). Signatures: pub fn load_state(root: &Path) -> McpLoadState with pub struct McpLoadState { pub present: bool, pub content: Option<String>, pub read_error: Option<String> } (present via path.is_file(); content via read_to_string only when present; read_error = Some(e.to_string()) otherwise); pub fn probe_json(text: &str) -> Result<(), String> implemented as serde_json::from_str::<serde_json::Value>(text).map_err(|e| e.to_string()) — syntax-only, deliberately schema-blind per NFR-5; pub enum McpSaveOp { Unchanged, Write, Clear } deriving Debug/Clone/PartialEq/Eq; pub fn classify(file_present: bool, current: Option<&str>, buffer: &str) -> McpSaveOp with rules: blank := buffer.trim().is_empty(); blank && !file_present → Unchanged; blank && file_present → Clear (also purges blank residue files); !blank && current == Some(buffer) byte-exactly → Unchanged (NO normalization — cosmetic diffs always rewrite, pinned by test); otherwise → Write.
- Continuing mcp_io: pub struct McpApplyReceipt { pub op: McpSaveOp, pub short_sha: Option<String>, pub malformed: Option<String> }; pub fn apply_save(root: &Path, buffer: &str) -> Result<McpApplyReceipt, AppError> sequenced: (1) load_state(root); (2) op = classify(...); (3) Unchanged → Ok(receipt{Unchanged, short_sha: None, malformed: None}), zero file IO, zero git; (4) Write → malformed = probe_json(buffer).err() computed but NOT fatal; atomic_write(&repo_artifact(root, MCP_CONFIG_FILE), buffer) mapped to AppError::Io{op:"write .planner/mcp.json"}; sha = gitops::commit(root, UPDATE_SUBJECT, &[MCP_CONFIG_FILE.to_string()])?; receipt{Write, Some(first 7 chars), malformed}; (5) Clear → std::fs::remove_file mapped to AppError::Io{op:"remove .planner/mcp.json"}; sha = gitops::commit(root, CLEAR_SUBJECT, &[MCP_CONFIG_FILE.to_string()])?; receipt{Clear, Some(first 7), None}. Subjects as consts: pub const UPDATE_SUBJECT: &str = "settings: update mcp server configuration"; pub const CLEAR_SUBJECT: &str = "settings: clear mcp server configuration" (short imperative, NFR-9; parallels the existing 'settings: update stakeholders and identity' family).

- Given the editor containing the malformed fragment '{"servers":', when the operator presses Save, then the file is written VERBATIM with that fragment (bytes asserted), the checkpoint lands under the update subject, the dialog STAYS OPEN with an orange (theme::WARNING) inline line quoting the parse error and stating 'saved anyway', and no second commit is created.
- Given an unedited dialog (or a second immediate Save after a successful one), when Save is pressed, then classify returns Unchanged: no file write occurs (mtime/bytes provably untouched in test), no commit is created (HEAD hash identical), and the info toast 'MCP configuration already in sync' shows — zero commit churn per NFR-9.
- Given a temporary DIRECTORY THAT IS NOT A GIT REPO, when apply_save runs with a non-blank buffer, then it returns Err(AppError::Git{..}) while the file EXISTS on disk with the buffered bytes, and the dialog feedback explains that retrying Save will not re-create the commit — the failure is surfaced, never swallowed (FR-11 spirit).

## Edge cases and failure handling

- Trigger: the operator saves while a planning turn is running (dialogs carry no busy-guard — verified precedent at root.rs Import/Stakeholders arms). Required behavior: the rename-swap means the running turn's context reader (or the next build) observes either the complete old or complete new file, never a torn mix; the in-flight turn's state clone is unaffected and the NEXT turn picks up the new section. Preserved invariant: NFR-2 atomicity and NFR-3 per-process single-writer are undisturbed by a settings-class save.
- Trigger: .planner/mcp.json exists but is unreadable at open (permissions, non-UTF8 bytes). Required behavior: the field opens empty WITH the persistent 'saving will OVERWRITE' warning so the operator consents explicitly; the probe never runs on an empty buffer (Clear path). Preserved invariant: no silent destruction of unseen content.
- Trigger: git checkpoint fails after the disk write succeeds (hooks, lock contention). Required behavior: Err path with the explicit 'retry won't re-create the commit' message, dialog kept open, header dirty indicator truthful; recovery is a later turn's checkpoint or operator git. Preserved invariant: honest accounting — the app never reports a checkpoint it did not make.
- Trigger: rapid double-click of Save within successive frames. Required behavior: the first Save commits; the second classifies Unchanged (file now byte-equal) and no-ops. Preserved invariant: exactly-one-commit-per-distinct-change, no duplicate checkpoints.
- Trigger: buffer exceeding 4,096 characters. Required behavior: Save writes the COMPLETE file — the verified 4,096 clip applies only to the prompt FEED (context_build.clip with the '[…truncated…]' marker), never to disk; the char-count line telegraphs the clip threshold beforehand. Preserved invariant: the editor is byte-transparent; truncation is presentation-side only.
