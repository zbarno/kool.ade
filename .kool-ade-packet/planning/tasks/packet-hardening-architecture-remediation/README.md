## Phase evidence

- **P1 — artifact layout authority:** `src/artifacts/layout.rs` owns canonical paths and identifies migration-only legacy inputs. Runtime artifact paths route through the canonical layout; remaining old-path fixtures exercise migration. Layout containment checks and the serial all-target suite pass.
- **Issue-specific blocker explanations:** production explanations are generated from the saved task story, blocker report, acceptance evidence, verification results, and referenced project documents. New report schema v2 carries model-produced `human_choices` with issue-specific labels, meanings, consequences, and IDs; the read-only explanation generator turns those into the ELI5 problem, steps, and optional evidence-backed recommendation. Rust checks that every displayed choice matches the saved report and rejects invented choices. Cache keys include the task story, report, documents, and current prompt. The quota example is test-fixture data, not a production option set. Focused generator/cache/report tests and the full serial suite pass.
- **P2 — artifact migration:** fresh connection creates the modular product documents, config, and open-items only under `.kool-ade-packet/`. Existing files move through a preflighted schema-v2 migration; conflicting targets preserve both copies and stop before mutation. Migration tests cover idempotency, restart after interrupted checkpointing, unrelated staged-file preservation, task identity and report-path updates, queue/retry state, workflow approvals, and implementation evidence. Pre-migration transaction rollback runs before the move, keeping its legacy-path writes inside the migration boundary. The serial all-target suite passes.
- **P3 — Git index isolation:** Packet now commits only literal pathspecs authorized by the transaction, using `git commit --only` under a cross-process checkpoint lock. Before staging, it snapshots the authorized index entries; it restores them on no-op, failure, and cancellation, and after success it restores any pre-existing staged edit that overlapped an authorized file. Unrelated staged, partial, unstaged, and untracked work remains intact. Imports now pass the exact copied file and companion paths instead of authorizing their whole directory. `gitops::stage` trusts the exit status and treats successful stderr warnings as success. Regression tests cover multiple staged files, partial stages, overlap, failed and no-op commits, cancellation, concurrent Packet commits, and stderr warnings. `cargo test --offline --all-targets --quiet -- --test-threads=1` passed (495 library tests; integration targets passed; one separately gated migration repair remains ignored).
- **P4 — typed workflow and recovery state:** Implementation lifecycle and PR states are enums with user labels derived from typed values. State records write schema version 1; old labels migrate once, and unknown persisted states become visible Needs attention records. Queue blockers persist `FailureKind`, `RecoveryDisposition`, and message under their own schema version; the sole prose classifier runs only while upgrading old queue entries. New implementation reports use typed status plus an AI-produced blocker disposition, so active retry behavior uses the reported cause instead of scanning role names or words in action text. UI recovery labels use the typed disposition. `cargo test --offline --all-targets --quiet -- --test-threads=1` passed (499 library tests; integration targets passed; one separately gated migration repair remains ignored); `cargo fmt --all --check` and `git diff --check` passed.
