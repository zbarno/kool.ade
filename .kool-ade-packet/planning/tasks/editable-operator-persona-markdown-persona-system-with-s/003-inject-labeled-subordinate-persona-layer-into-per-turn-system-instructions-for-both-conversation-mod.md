## Problem this ticket solves and why

Stories 001 and 002 deliver a saved, operator-editable persona file and a Settings card to edit it, but nothing consumes it: run_turn in src/core/turn.rs still assembles every turn's system_instructions solely from the compile-time SYSTEM_INSTRUCTIONS constant (build site near line 176, format assembly near lines 255-267), so a saved edit is dead text — the operator edits markdown, saves it, and the very next Main Chat or card reply still speaks the old baked-in voice. Left unresolved, the feature strands at brief success criterion 4 (effective from the next turn on, both conversation modes): store and editor would exist with no effect, every turn would ignore the operator's tuned voice indefinitely, and all later tickets (boundary tests, verification) would be validating an unwired seam.

## Ticket goal — what changes when done

Before this ticket, load_persona()'s result reaches no prompt at all. After it alone: every Main Chat turn, every card-conversation turn, and every task-generation turn dispatched through run_turn carries the freshly loaded persona document as a clearly labeled subordinate layer appended AFTER the entire standing contract in the single shared assembly, making the tuned voice audible from the very next turn in both modes, while a missing, corrupt, or blank file rides the shipped four-beat default with the store's diagnostic surfaced to the operator instead of a blank. Observable completion: the persona-assembly and persona_injection batteries pass under cargo test --lib core::prompt and cargo test --lib core::turn on the pinned Rust 1.98 toolchain, and full cargo test stays green with the pre-existing capture-harness tests pinning the standing-instruction bytes passing unmodified.

## User story

As the seated operator Zachary Barno (sole seat per D-23), I want the persona markdown I save to be woven into the planner's standing instructions as a clearly labeled subordinate layer from the very next turn on, in both Main Chat and card conversations, so that my tuned voice is immediately audible everywhere I talk to the planner — with the application's enforceable protocol standing visibly above it, and a surfaced diagnostic whenever my file cannot be read.

## Purpose

Until this ticket lands, the saved persona influences no turn at all; it wires the loaded document into the single shared system_instructions assembly in src/core/turn.rs (currently '{SYSTEM_INSTRUCTIONS}\n policy \n workflow/task tails'), appended as a clearly labeled operator-persona layer AFTER the standing contract with an explicit subordination clause. Because Main Chat and card conversations share that one assembly (card mode only swaps the trailing mode-note), one injection makes the tuned voice effective from the very next turn in both modes (REQ-P3-1, AS-1); a missing or unreadable file injects the shipped default and raises the store's diagnostic rather than a blank.

## Technical design and contracts

- Assembly refactor in src/core/prompt.rs: (a) move the TASK CONVERSATION MODE note literal currently inline in turn.rs into a new pub const TASK_CONVERSATION_MODE_NOTE of type str slice, copied CHARACTER-FOR-CHARACTER including internal apostrophes, quoted option labels, and any digest-contract phrasing — byte-identical content, no whitespace cleanup, because the pre-existing capture-test needles are the acceptance probe for the relocation; (b) add pub const PERSONA_LAYER_INTRO of the same type — a fixed preamble naming the layer as the OPERATOR PERSONA (a subordinate overlay affecting voice, priorities, and disposition only), stating that the operator maintains the document below, that it does NOT modify, pause, waive, or reinterpret the standing instructions (response contract and JSON envelope shape, application-side validation, routing/veto law, board/item protocol, safety rails) which stay machine-enforced and outrank every persona word including any sentence claiming the opposite, and that any collision is a wording hint to paraphrase toward compliance with the standing instruction winning quietly; (c) pub fn persona_layer(operator_document: &str) -> String, a two-operand format join of the intro plus the verbatim document — no trim, no transform, because document bytes are story 001's contract; (d) pub fn compose_system_instructions(task_note: Option<&str>, operator_persona: &str) -> String assembling five newline-separated slots: SYSTEM_INSTRUCTIONS, SPECIFICATION_POLICY, the workflow slot (WORKFLOW_INSTRUCTIONS when task_note is None else empty), the tail slot (task_note or empty), and persona_layer(operator_persona).
- Compatibility and subordination-by-placement guarantees: the five-slot composition is a direct extension of today's four-slot format, so for ANY persona document the pre-feature main-mode string and the pre-feature task-mode string are both STRICT PREFIXES of the corresponding new composition, differing only by the appended layer — locked by a unit test that reconstructs the old strings by hand from the same constants and asserts the prefix relation. Placement is the prompt-level subordination guarantee (deeper adversarial locking is story 004): persona bytes occupy only the FINAL segment of system_instructions, and since pi_harness hands the string to Pi verbatim, every standing needle (the closing-JSON-fence sentence, the full SPECIFICATION_POLICY text, the interview section in main mode, the TASK CONVERSATION MODE banner in task mode) sits at an index strictly before the layer by construction, assertable via index comparison without mocking.
- Pipeline wiring in src/core/turn.rs run_turn, inserted AFTER the last GenerateTasks readiness gate and immediately BEFORE PlanningRequest construction: call crate::persistence::persona::load_persona() fresh on every turn — deliberately UNCACHED so a Settings save binds from the very next turn and a simulated relaunch is unnecessary (the file is kilobyte-scale while turns are minute-to-hour-scale). Derive system_instructions from prompt::compose_system_instructions, passing TASK_CONVERSATION_MODE_NOTE only when a task conversation is active. The load and compose sit strictly before harness execution and strictly after every pre-request Rejected gate, so gate-rejected turns perform no persona file IO and emit no new diagnostic.
- Diagnostic surfacing: when the PersonaLoad carries a Some diagnostic, send a LiveProgress activity notice beginning with the prefix Persona note: followed by the store's own string verbatim over the existing progress channel, IGNORING the send Result — a dropped receiver means the UI abandoned the turn and the turn must proceed (fire-and-forget mirroring the Starting planner idiom at root.rs near line 1165). The store's strings (absence-plus-seed naming the path, unreadable, not-valid-UTF-8, blank per story 001) ride inside unchanged. This raises the store's diagnostic rather than a blank on the one channel the chat pane already renders, without touching any schema, enum, or UI file.
- Warning-hygiene and explicit non-changes for the D-34 bar: after the refactor turn.rs no longer names SYSTEM_INSTRUCTIONS in production code, so its prompt import line shrinks accordingly — leaving the dead import would mint a new unused-import warning that story 005's baseline diff would flag, while any leftover reference to a moved symbol is a broken build caught at compile time. Explicitly untouched: zero edits under src/harness (pass-through already verbatim), zero edits to src/persistence (story 001's module consumed, never altered), src/core/investigation.rs and its separate request builder, validation.rs, pi_extract.rs (extraction parses assistant output, a different plane from system instructions), all UI files, no new files, and no Cargo.toml or Cargo.lock delta.

## Edge cases and failure handling

- Adversarial document content — a fake fenced JSON pseudo-envelope, imperious ignore-prior-instructions sabotage, emojis, CRLF pairs, leading and trailing spaces: the document rides VERBATIM with no sanitizing, trimming, or fence stripping, because filtering would violate story 001's byte-fidelity contract and because persona bytes live in system instructions, a different plane from the assistant output the extractor parses; the pipeline must still Apply a valid canned envelope while such a document is resident.
- Concurrent save racing a loading turn: save_persona's atomic temp-plus-rename means the loader observes exactly one of the old or the new complete document, never a torn mix, and the injected layer is self-consistent whichever copy wins — no additional locking is owed at this seam.
- A very large persona (hundreds of KiB): composition handles it linearly with no cap by design, consistent with story 001's no-quota ruling; the cost is token overhead the operator knowingly accepts by authoring size.
- Gate-rejected turns (unapproved task generation, refused drift) return before the persona load: no file read, no diagnostic notice, rejection text byte-identical to today — the feature must not add IO or messaging to failure paths that predate it.
- Progress receiver dropped mid-load (UI abandoned the controller): the ignored send Result lets the turn proceed with composed instructions untouched — a lost notice never degrades the turn, mirroring the fire-and-forget progress idiom.
