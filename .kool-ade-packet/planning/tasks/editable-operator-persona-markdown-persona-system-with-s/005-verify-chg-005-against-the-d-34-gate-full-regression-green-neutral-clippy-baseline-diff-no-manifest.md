- Capture procedure, identical on both sides: (cd WORKTREE && cargo clippy --all-targets 2> RAW.stderr >/dev/null; echo EXIT=$? > RAW.rc). Append --offline to the cargo invocation only if the registry is unreachable with a warm cache; the lock file must never be touched to satisfy the environment. RAW.rc must contain EXIT=0 (nonzero is an environmental failure to re-run, never a warning verdict). Stderr is the complete artifact; stdout progress noise is discarded. Expect scale near the measured base: roughly 109 warning headers; a grossly different magnitude signals environmental contamination and is investigated before any pass/fail conclusion.
- Normalization and set diff - the binding operational form of D-34's 'no NEW warnings': awk passes over RAW.stderr: skip package-summary trailer lines matching ^warning: `; start a new unit on header lines ^warning(\[[0-9]+\])?(: |[A-Za-z]); replace [0-9]+ runs in the header with N; on the FIRST subsequent ' --> ' line keep the file path with its ':line:col' suffix stripped; emit '<normalized header> @ <file>'. Pipe through LC_ALL=C sort -u to form the set. Rationale: file-granular keys make moved-but-identical warnings (shifted by the feature's own inserted lines) key-invariant, while sort -u collapses the per-configuration duplicates (base measured 103 vs 89 with 89 duplicates). Verified empirically: the fresh base capture yields 60 unique keys from 109 headers. Gate: comm -13 PRE.set POST.set > added.lines must be EMPTY (zero added lines - the stated bar); comm -23 PRE.set POST.set > removed.lines is informational only: disappearing pre-existing warnings are lawful debt retirement under D-34 but must be listed in the record, never suppressed.

## Edge cases and failure handling

- Compiler duplication across compile configurations: the same warning prints once per target flavor (base measured 103 lib-test vs 89 lib with '89 duplicates'), so raw line counts move for reasons unrelated to code quality - only the uniqued, normalized message@file sets may be compared, and that rule is written into the record's method section.
- Pre-existing warnings physically moved by the feature's inserted lines: file-granular keys make a moved-but-identical warning key-invariant, so the gate sees only truly new (message, file) pairs; the trade-off - two different warnings collapsing to the same key in one file - is acknowledged in the record as residual conservatism in the pass direction, compensated by the identifier-scoped symbol gate.
- Dirty development worktree (generation-time observation: eleven modified files plus the untracked batch directory): verification runs exclusively in freshly created clean worktrees; if a capture accidentally starts in the main checkout the record must declare VOID and re-run, and the ticket ends only after proving the main checkout's status listing is unchanged.
- Offline or flaky environment: an unreachable registry triggers the --offline retry against the warm cache without any lock mutation, and a red integration test earns exactly one disclosed re-run in RECORD.md before blocking - NFR-8 demands a passing full suite, and masking instability with reruns or ignores would falsify the gate.
- A later batch landing on master before this gate runs: the backward walk selects the newest commit whose src-plus-manifest diff still equals the seven-path set, every skipped commit is listed in the record, and a walk that would skip commits touching OTHER src paths halts instead of swallowing a scope breach.
