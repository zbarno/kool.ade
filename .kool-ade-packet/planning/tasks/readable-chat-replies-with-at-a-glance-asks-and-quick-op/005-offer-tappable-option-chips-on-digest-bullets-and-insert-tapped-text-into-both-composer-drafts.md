Feature: Readable Chat Replies with At-a-Glance Asks and Quick Option Chips (CHG-003)

Status: Individually validated; see batch index for generation status.

## Problem this ticket solves and why

With story 4 landed, the planner's outstanding ask is floated but a reply like '- Yes, bind Aurora' / '- No, keep Postman' still forces the operator to re-key a phrase staring at the screen — exactly the friction the operator asked to remove. Worse, without chips the operator cannot tell at a glance which bullets are discrete choices versus prose, so every decision costs re-typing or guesswork, and the digest's promised speed is lost on the most common reply shape (binary/options questions). Untouched, success criterion 3 of CHG-003 fails wholesale: no tappable options anywhere in Main Chat or card chats.

## Ticket goal — what changes when done

After this ticket alone, whenever the lifted digest's bullets enumerate 2–6 explicit options (leading Yes/No word, 'Option N', or a single letter followed by '(', ')' or '.'), a tappable chip row appears directly beneath the lifted block on Main Chat/task tabs and beneath the ask inside the card's answer frame; tapping a chip APPENDS that bullet's exact text to that chat's composer draft, focuses the editor with the caret at end, and sends nothing — verifiable by a synthetic click flipping the draft while the send flag stays false and a follow-up keystroke lands after the inserted text.

## User story

As the seated operator facing a planner reply that offers me Yes/No or Option 1/2, I want to tap the option chip so the exact option text lands in my composer draft with the caret ready to edit or send, so I stop re-typing phrases on screen while freeform typing stays unrestricted at all times.

## Purpose

Even with the lifted digest, choosing between enumerated options forces the operator to re-type a phrase that is sitting in front of them, friction the operator explicitly asked to remove without ever limiting freeform answers. This ticket adds the option-grammar detector over digest bullets (case-insensitive leading tokens 'Yes', 'No', 'Option N', single letter followed by '(' or ')' or '.', 2–6 recognized options or no chips), a compact chip-row widget rendered beneath the digest on both surfaces showing the token plus up to ~40 characters of descriptor with hover revealing full text, and tap-to-insert wiring that APPENDS the option's exact text to that chat's composer draft, focuses the input with caret at end, and sends nothing — the composer remains fully interactive at all times; insert-path unit tests cover draft mutation-without-send, caret/focus, single-option and >6-option suppression on both the Main Chat and task_chat composers, with no Cargo.toml delta.

## Technical design and contracts

- DETector (pure, in story-4's src/ui/reply_tail.rs): pub struct OptionChoice { pub token: String, pub text: String } where text is the detector-cleaned bullet (marker stripped, edges trimmed, interior untouched — the EXACT inserted text) and token is the canonical display token; pub fn digest_choices(tail: &ReplyTail) -> Vec<OptionChoice> returns empty unless tail.kind == TailKind::Digest, else scans tail.bullets in order with case-insensitive precedence: (1) leading ASCII-alphabetic word equal to 'yes'/'no' → token "Yes"/"No", remainder after the word; (2) leading word 'option' followed (after optional spaces) by ≥1 decimal digits → token format!("Option {digits}"); (3) single ASCII letter immediately followed (no space) by '(', ')' or '.' → uppercased letter token. Bullets failing all three are skipped; matches are kept in bullet order and RETURNED ONLY IF 2 <= matches.len() <= 6, otherwise an empty Vec (all-or-nothing; a 1-match or 7-match digest renders zero chips). pub fn open_digest_choices(messages: &[ChatMessage]) -> Vec<OptionChoice> = open_ask_index(messages).map(|idx| digest_choices(&parse_reply_tail(&message_text::readable(&messages[idx])))) unwrapped_or_default — reusing story 4's selector so answered digests (later User message) and non-lifted replies yield no chips.
- DISPLAY + MUTATION helpers, same file, pure and unit-tested: pub fn choice_label(choice: &OptionChoice) -> String builds "{token}" plus, when a descriptor remains, ' ' + the remainder after stripping LEADING characters in the set \s , ; : . ! ? - – — ( ) (and, if that still begins with '(', dropping the shortest leading balanced parenthesized group within 80 chars, then trimming leading separators once more), truncated at DESCRIPTOR_CAP_CHARS: usize = 40 characters plus '…' when longer. pub fn join_choice(draft: &mut String, text: &str, sep: char) { if !draft.is_empty() && !draft.chars().next_back().is_some_and(char::is_whitespace) { draft.push(sep); } draft.push_str(text); } — sep '\n' for multiline composers, ' ' for the collapsed singleline card composer; no trimming of existing draft content.
- CHIP ROW widget, same file (egui half): pub fn paint_chip_row(ui: &mut egui::Ui, choices: &[OptionChoice], enabled: bool) -> Option<usize>. Empty input → immediate return, zero layout. Else ui.horizontal_wrapped with one cell per choice: label = choice_label at FontId::proportional(12.0) via ui.painter().layout_no_wrap (theme::TEXT, or theme::TEXT_DIM when !enabled), cell = galley size + vec2(14.0, 8.0) allocated with Sense::click() when enabled else Sense::hover(); paint rounded rect radius 10 filled theme::CHIP_FILL stroked 1.0 theme::CHIP_BORDER (hover upgrades stroke to theme::ACCENT), galley inset (7,4). Enabled cells take resp.on_hover_text(choice.text) — the tooltip is ALWAYS the exact insert text, making tap-to-insert semantics discoverable. Returns the first clicked index (effectively ≤1 per frame).
- FOCUS + CARET, same file: pub fn pin_caret_to_end(editor: &egui::widgets::text_edit::TextEditOutput, ctx: &egui::Context, draft: &str) { let n = draft.chars().count(); let mut st = editor.state.clone(); st.cursor.set_char_range(Some(egui::text::CCursorRange::one(egui::text::CCursor::new(n)))); st.store(ctx, editor.response.id); editor.response.request_focus(); } — the exact pattern prescribed by TextEditState's vendored doc-test; request_focus is honored next frame, and because the stored range is forced to the post-append length the caret lands at end irrespective of any previously persisted cursor (egui's cursor_at_end default would otherwise leave a stale midpoint when the editor already carried a saved range).
- MAIN CHAT + TASK-TAB wiring (src/ui/chat_pane.rs): paint_with_hint declares let mut chip_fired = false; before the scroll scope and threads draft: &mut String, chip_fired: &mut bool, interactive: bool (= !busy) into paint_message's private signature (story 4 already added lift: bool; sole caller is the loop). In the Agent branch, after markdown::paint and story 4's if lift { paint_open_ask(ui, &tail); }: if lift { let choices = digest_choices(&tail); if let Some(i) = paint_chip_row(ui, &choices, interactive) { join_choice(draft, &choices[i].text, '\n'); *chip_fired = true; } } — chips render strictly BELOW the lifted block (stable story-4 footprint above them) and only on the lifted (still-open) reply, so stale digests never grow chip rain. Composer: replace ui.add_sized(...) with let editor = TextEdit::multiline(draft).hint_text(hint).id_salt(composer_id).desired_width(f32::INFINITY).desired_rows(2).frame(Frame::NONE).interactive(editable).show(ui);, composer_id threaded as a new private parameter ("main_chat_composer" from paint, "task_tab_composer" from paint_task); immediately after, if chip_fired { pin_caret_to_end(&editor, ui.ctx(), draft); }. The send circle, its enable logic, Ctrl/Cmd+Enter and the Intent contract are byte-identical — a chip click lands far from the send circle, so send can only be false.
- CARD wiring (src/ui/task_chat.rs): inside the ACCENT_SOFT frame closure, after the action-label block and before the Stop/composer section, when !active: let choices = open_digest_choices(&messages); let mut chip_fired = false; if let Some(i) = reply_tail::paint_chip_row(ui, &choices, !s.task_reply_busy()) { if let Some(draft) = s.task_draft(key) { reply_tail::join_choice(draft, &choices[i].text, if expanded {'\n'} else {' '}); chip_fired = true; } }. composer gains one parameter chip_fired: bool (the mutually-exclusive 'Add context' call site passes false); both its TextEdit::singleline/multiline constructions switch from ui.add to .id_salt(if answer {"task_answer_composer"} else {"task_context_composer"}).show(ui) (ids already scoped per card by paint's outer push_id), and if chip_fired { pin_caret_to_end(&out, ui.ctx(), draft); } after each. needs_answer computation, heading/action strings, Stop-reply/Assign/Approve/Retry/Stop-task logic, and transcript() (story-4 lift stays inside scrolled history) are byte-untouched — chips anchor at the answer-control cluster, not inside the history scroll. theme.rs edit is doc-comments only: the two reserved constants' comments flip from 'held for story 5' to 'used by the CHG-003 chip row'; no new colors (hover state reuses ACCENT).

## Edge cases and failure handling

- Suppression boundaries are all-or-nothing: exactly 6 matches render 6 chips, 7 matches render zero — tested at both borders, because a half-chipped digest (options as chips, twins as prose) would misrepresent the model's offer; likewise 2 is the floor, 1 renders none.
- False-positive guard: bullets like 'I recommend Postman', 'Never', 'NOTE: verify', 'Option TBD' (no digit), or 'A nice compromise' (letter not immediately punctuated) must classify non-options in the vector table, since any one leaking a chip teaches the operator a phantom option.
- Already-focused draft: if the operator taps a chip while the composer already holds focus mid-thought, join_choice inserts at the caret-relevant END (draft tail) rather than mid-text, and pin_caret_to_end overrides any stale persisted cursor — no text loss, no double separator when the draft already trails whitespace (tested: trailing space/newline cases push no extra separator).
- Busy/racing: with a turn streaming (busy=true Main Chat; active or task_reply_busy card), chips paint but allocate with Sense::hover only, so the click neither mutates the draft nor focuses the editor — drafts under an in-flight save must not churn; the block re-enables atomically on the next idle frame.
- Unicode drafts: drafts containing multibyte content (e.g. accented or emoji) before insertion — join_choice slices nothing and push_str is boundary-safe; CCursor::new(draft.chars().count()) counts CHARACTERS not bytes, which is exactly the index mode egui's CCursorRange expects; a corrupted envelope reply (shield note from message_text) classifies non-Digest, so no chip can ever derive from JSON remnants.
