## Problem this ticket solves and why

At frozen base 28ba698 the centralized class-to-hue table theme::board_hue (src/ui/theme.rs:21-30) disagrees with the approved CHG-002 recorded-defaults table on exactly two arms: task-story cards (discriminant None) map to a cool blue rgb(116,187,235) instead of the ACCENT sage house hue rgb(218,223,212), and Assumption maps to the WARNING amber instead of lavender rgb(190,168,255). Consequently a mixed fixture board fails AC 6's at-a-glance hue check, the board's own legend row mislabels two of the five classes it advertises, and the approved active-state design cannot cohere: a running Task card does not even wear the house hue as its base, so REQ-F20-1, the Task-specific clause of REQ-F20-2, and the DANGER-exclusion proof all ride on this one wrong table and remain unenforced until it is corrected.

## Ticket goal — what changes when done

After this ticket alone, theme::board_hue returns the approved five-row table verbatim (None/Task to ACCENT sage 218,223,212; Question to PURPLE 167,139,250; Ambiguity to SUCCESS 107,212,144; Assumption to lavender 190,168,255; Ownership to pink 232,145,190) and no card hue claims DANGER red 255,107,107; theme::board_frame gives a running Task card a heavier 2.5 px ACCENT stroke over a 0.22 gamma-blend fill versus its idle 1.0 px over 0.12, while every item class keeps the ACCENT stroke upgrade over its idle class-hue stroke. Observable completion: the rewritten-plus-new theme unit tests pass (table equality, DANGER exclusion, pairwise distinctness, active-versus-idle inequality, badge-vocabulary sharing), cargo clippy --all-targets --offline is warning-free, cargo test --offline is green at net +3 tests, git diff names only src/ui/theme.rs, and a mixed fixture board reads sage/purple/green/lavender/pink with printed class headers intact.
