## Approved scope mapping

- Scope 1: Workspace-menu 'Open workspace' action: detached self-spawn of the running binary; the spawned instance inherits the launch environment (PACKET_HOME, PACKET_TURN_TIMEOUT_SECS, PACKET_PI_BIN) and lands on the initial screen

- Scope 2: Directory browser on the initial screen (browse button beside the path field): navigate folders, indicate which are git working trees, place the selection into the existing path field without auto-submitting

- Scope 3: GitHub URL entry on the initial screen: parse an https://github.com/{owner}/{repo}(.git) URL, clone it with the system git CLI into $HOME/{repo}, then feed the result through the same attempt_connect path (validate, recover, load, bootstrap, hydrate)
- Success criterion 1: Pressing 'Open workspace' in the Workspace menu of a connected workspace spawns a second, detached Packet instance whose window presents the initial screen, while the first instance's in-flight work continues undisturbed.
- Success criterion 2: From the initial screen the operator selects an existing local git working tree using the browse button (directory browser) and opens it.
- Success criterion 3: Pasting a github.com URL on the initial screen clones the repository with the system git CLI and opens it as a connected workspace, bootstrapping the planning scaffold if absent.

## Edge cases and failure handling

- Parallel environment mutators: chat_store tests flip PACKET_HOME under their private lock and git children mutate env inside shield scopes, so the probe's sentinel assertions could red-ghost a real pass if a rival test rewrites a variable inside the microsecond spawn window. Required behavior: at most ONE disclosed re-run of that test with --test-threads=1, recorded in RECORD.md; never an ignore attribute and never loosened equality - the inheritance contract must stay machine-checked.
- A later unrelated batch landing on the remote between the feature's last checkpoint and this gate: the backward V walk may skip only commits touching none of src/ or Cargo.*; the moment a candidate's diff introduces a path outside the eight-entry conformant table the walk HALTS and lists the offending commits - swallowing somebody else's scope breach would falsify reconciliation's (FR-18) input.
- Contaminated capture environments: a cold or offline cargo cache, a stale incremental target dir, or a drifted toolchain inflates or deflates the warning population. Treat a nonzero capture rc as an environmental re-run (never a warning verdict), investigate gross scale deviations from the ~108 base neighborhood BEFORE concluding anything, and append --offline only against the warm cache without ever touching the lockfile.
- Headless runners cannot open eframe windows (labeled assumption; no GUI test exists in-tree): the in-process chain tests A-D are the CI-proof share and must stand alone; the runbook is the evidentiary vehicle for the L1/L3 window-level observables, and no gate check may silently widen to paper over an unrunnable GUI leg - an unavailable display is a stated pending exhibit, never a PASS.
- Race-test settlement variance: thread scheduling decides which performer wins the rename, so winner/loser identities shift between runs. Assertions are class-membership only (healthy tree plus permitted loser results plus no scratch remnants), never identity, so a legitimate scheduling change cannot red a correct implementation, while the 5-iteration loop makes intermittent corruption loud.
