The architectural thesis

The model proposes.
The software enforces.

Give an agent a vague goal, a shell and a prayer, and it'll ship something. The missing control plane is durable intent, narrow permissions, explicit approvals, repeatable execution, independent verification and a Git history that remembers what everyone agreed to.

03 / Why any of this?

Guardrails, not magic.

It's not architecture for architecture's sake. Every boundary exists because autonomous software development gets weird when an agent can make changes faster than humans can notice bad assumptions.

01 / TRUTH

Git is memory. Spec is contract.

Approved intent and verified implementation are separate. The spec changes when evidence says it should, not when the model feels optimistic.

02 / SAFETY

Capability is rented.

Agents receive scoped tools, brokered dependencies and isolated execution. No automatic master key to the host.

03 / SCALE

Parallel, not pandemonium.

Task clones, Git leases and dependency graphs let workers cooperate without writing over each other's changes.

04 / QUALITY

Homework checked by someone else.

Independent reviewers and runtime QA require real evidence before declaring victory.

05 / PORTABILITY

Your stack, not ours.

Build/test/start recipes describe the user's project. Rust powers Kool.ad/e, but your project doesn't have to use Rust.

06 / EVOLUTION

New tricks need permission.

Man.ager can propose improvements to itself, but execution still needs approval, isolation, review and a PR.

04 / The build order

The roadmap is a dependency chain.

Durable shared state first, standardized execution second, then progressively more autonomous agents within the same constraints.
