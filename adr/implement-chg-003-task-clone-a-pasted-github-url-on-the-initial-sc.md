# CHG-003-TASK-clone-a-pasted-github-url-on-the-initial-screen-and-open-it-through-the-existing-connect-path — Clone a pasted GitHub URL on the initial screen and open it through the existing connect path

## Problem this ticket solves and why

To bring a brand-new project into Packet the operator must first open a terminal, know the git URL, run git clone somewhere on disk, remember where, then return to the initial screen and hand-type that absolute path — every hop inviting typos that burn a round-trip through attempt_connect's InvalidRepo banners. The initial screen (src/app/welcome.rs) has no way to name a remote repository at all; the browse button added by the completed dependency story only helps for directories that already exist locally. Until this ticket lands, cold-starting any not-yet-cloned workspace on Packet requires leaving the app, which is exactly the friction the approved brief's success criterion 3 removes by making a pasted github.com URL a first-class connect input.

## Ticket goal — what changes when done

After this ticket (building on story 2's initial-screen work), pasting an https://github.com/{owner}/{repo}(.git) URL into a new GitHub URL row on the initial screen and pressing 'Clone' (or Enter inside that field) clones the repository off-thread with the system git CLI into $HOME/{repo}, then fills the existing conn_path field with the canonical destination and drives the byte-identical submit_connect → attempt_connect sequence — validation, transaction recovery, state load, planning-scaffold bootstrap, chat hydration, queue load — finishing on Screen::Connected with the same success toast a typed path earns. Observable completion: an offline perform_clone(local source) → attempt_connect test yields a connected Project with bootstrapped scaffold, and a real GitHub URL verified in the manual smoke connects with no prior terminal work; invalid URLs, failed clones, and pre-existing non-working-tree destinations all leave the operator on the initial screen with a specific banner.

## User story

As the seated operator (Zachary Barno, D-23) starting from Packet's initial screen, I want to paste a github.com repository URL and press one Clone button so that I get a fully connected workspace — planning scaffold bootstrapped, chat hydrated — without ever opening a terminal or learning where Packet stored the clone.

## Purpose

Bringing a new project into Packet today requires a separate terminal git clone before the app can see it; this task adds a GitHub URL entry to the initial screen that parses https://github.com/{owner}/{repo} (with optional .git suffix) with a clear rejection for anything else, clones it with the system git CLI using vector arguments into $HOME/{repo} per the D-03/NFR-5 constraint, then feeds the resulting path straight through welcome::attempt_connect so validation, transaction recovery, state load, planning-scaffold bootstrap if absent, and chat hydration all run exactly as they do for a typed path, with friendly errors for bad URLs, failed clones and pre-existing non-working-tree destinations.

## Technical design and contracts

- Add to src/app/welcome.rs a pure, std-only parser: pub struct GithubTarget { pub owner: String, pub repo: String, pub url: String } where url is the CANONICAL rebuilt form https://github.com/{owner}/{repo}.git, and pub fn parse_github_url(raw: &str) -> Result<GithubTarget, String>. Grammar: trim; require lowercase-equal 'https' scheme; the authority between '// ' and the first '/' must equal 'github.com' case-insensitively with NO userinfo, port, query, or fragment anywhere in the remainder; the remainder must be exactly '/{owner}/{repo}' (optionally ending in '.git' or a single trailing slash), two non-empty segments each matching ASCII-alphanumeric plus '-' '_' '.', starting/ending alphanumeric, and not containing '..'. 'HTTPS://GITHUB.COM/Octo/Repo.GIT' is accepted with original segment case preserved. Every rejection returns a distinct operator-actionable sentence containing the canonical shape, e.g. empty → 'Paste a github.com URL to clone, e.g. https://github.com/octocat/hello-world'; host mismatch → 'Only https://github.com/{owner}/{repo} URLs can be cloned here (got gitee.com).'
- Add to welcome.rs the clone mechanics, each unit-testable offline: pub fn clone_destination(repo: &str, home: &Path) -> PathBuf (pure: home.join(repo)); and pub fn perform_clone(source: &str, repo: &str) -> Result<PathBuf, AppError> flowing: locate home via std::env::var('HOME') (absent/blank → AppError::Io { op: 'locate home directory' , detail 'Set $HOME …'}); dest = clone_destination; if dest.is_file() → Err(InvalidRepo { path: dest-lossy, detail: 'a file already occupies that name' }); if dest.is_dir() → Ok(dest) IMMEDIATELY (already cloned — reconnect through the existing path, or let attempt_connect later raise the legacy 'no .git directory found' banner for a foreign directory; no re-clone); else home must be a dir (Io 'prepare clone parent'); sweep stale scratch: read_dir(home), best-effort remove_dir_all every entry whose name starts with "{repo}.packet-cloning."; scratch = home.join(format!("{repo}.packet-cloning.{}", std::process::id())); gitops::clone_repo(source, &scratch); sanity scratch.is_dir() else Git error; std::fs::rename(scratch, &dest) (atomic within $HOME) with best-effort scratch removal on failure → Io { op: 'place cloned repository' }; Ok(dest). The scratch-plus-rename invariant: $HOME/{repo} can never exist half-written even if the app or machine dies mid-download.
- Add to src/core/gitops.rs: pub fn clone_repo(source: &str, dest: &Path) -> Result<(), AppError> built as ['clone', source, dest.to_string_lossy()] and dispatched through the existing private run(cwd, &[&str]) with cwd = dest.parent() (which callers guarantee exists) so the NFR-5 vector-arg/no-shell guarantee stays centralized; nonzero exit → AppError::Git { cmd: format!("clone {source}"), detail: stderr.trim() falling back to stdout.trim() when blank }. No other gitops function changes.

## Edge cases and failure handling

- Credentials/quirk smuggling: a pasted URL with userinfo ('user:token@github.com/...'), a query string, a fragment, or a port is rejected at PARSE time before any thread or subprocess, so secret-bearing strings never reach git's argv or git's stderr; only the canonical rebuilt URL is ever cloned.
- Crash or quit mid-download: the worker clones into $HOME/{repo}.packet-cloning.{pid} and renames atomically, so a killed app (or power loss) can never leave $HOME/{repo} half-populated; leftover scratch dirs are swept at the START of each new clone for the same repo; an orphaned git process may keep downloading into the scratch dir after the app dies — accepted v1 limitation (no cancel affordance in scope), harmless to the real destination.
- Two Packet windows cloning the SAME repo simultaneously (possible once story 1's detached-spawn ships): different pids give distinct scratch dirs, one rename wins, the loser's rename fails and surfaces 'place cloned repository' with its scratch cleaned up; the winner's tree is healthy and the loser can retry (which then hits the existing-dest fast path).
- Non-UTF-8 or spaced HOME: all destination math stays in PathBuf (lossy conversion only when serializing into conn_path/display); attempt_connect's canonicalize then treats the string exactly like a typed path, including its existing 'could not open that path' behavior for unusable values.
- Very large repositories: no progress percentage and no cancel button (both out of scope, deliberately); the threaded design keeps EVERY UI frame responsive during the fetch (contrasted with a synchronous clone, which would freeze the window), and the pulsing status line communicates life via request_repaint.
- Whitespace-only URL input: the Clone button is disabled whenever the trimmed URL is empty and begin_clone double-guards, mirroring submit_connect's empty-path silence.
