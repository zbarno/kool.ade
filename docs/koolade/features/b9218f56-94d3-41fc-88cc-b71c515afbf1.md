## Intent

Let an operator start a regular Kool.ad/e task from one GitHub issue reference. A faithful, one-time snapshot carries the upstream discussion, links, and provenance into the task so the operator can plan and deliver work without re-entering context.

## Desired Behavior

An operator selects GitHub Issue in New Task and enters one reference. If a bare number leaves the source repository uncertain, the form asks where the issue lives before making any CLI request. The approved GitHub CLI reads with the operator-selected existing `github.com` identity. The app leaves account selection unchanged and reports a recoverable failure if it cannot bind the read to that identity. The operator sees progress and can cancel until saving begins. Successful import opens Planning Work details for the saved task, with its issue context and any omission or transfer warning. Recoverable failures explain the next step and keep the entered reference.

A successful ordinary Git-validated open durably registers the project's identity and original private store, including when an existing project next opens with its checkout. With the checkout unavailable, the app uses the authoritative saved binding to recover issue intake and saved snapshots from the original private store. If the binding is missing or ambiguous, the app shows a recoverable blocker and directs the operator to restore access to the checkout and reopen through the ordinary Git-validated route. The blocked reopen preserves the original private state. Repository and implementation operations remain gated while the checkout is unavailable.

A context-only Man.ager operation delivers the full snapshot alongside ordinary task context at initial intake and after restart. Delivery belongs to the current project, task, and operation instance and ends when any of them changes. The task keeps its original goal and follows the ordinary planning and delivery workflow. Later GitHub edits leave the saved snapshot unchanged.

## Scope

- New Task reference intake, repository resolution and fallback, an app-owned authenticated read-only issue lookup, bounded snapshot storage and delivery, sanitized root task details, recovery, and lifecycle integration.
- Missing-checkout recovery for already registered projects with an accessible private store, including issue intake, saved-snapshot access, and context-only delivery.
- Automated checks for import, persistence, Man.ager delivery and action authorization, and existing task types. Authorized real-UI validation covers failure recovery and a test pull request against the intended repository's `main`, left unmerged. Deliver F1 in this repository through a separate authorized feature-code pull request against `main`, also left unmerged.
- If putting the exact reviewed F1 specification on the published pin requires a separate documentation-only pull request, use the ordinary Kool.ad/e publication flow. An authorized repository operator must complete the protected merge of that documentation-only pull request before implementation.
- The temporary workspace-scoped development switch starts off, applies immediately, and is removed before the feature pull request.
- Excluded are other hosts, batch import, writes to the source issue, synchronization, watchers, polling, webhooks, re-import, fetching linked objects, importing discussions, releases, or standalone pull requests, changing GitHub authentication, and merging the test or feature-code pull requests.
