# Published specification changes

Published project knowledge consists of ordinary Markdown files in the
primary code repository. Kool.ad/e keeps drafts, interview transcripts,
approval records, and pending publication state in private local storage.

An explicit, authorized publication action validates the proposed documents,
checks the pinned published baseline for conflicts, and prepares a change on an
isolated branch. Normal pull request protections and review determine whether
the proposal becomes published. An open pull request is not a published
capability; only an accepted source revision can update published product
truth.
