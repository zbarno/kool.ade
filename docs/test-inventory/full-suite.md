# Full Rust test inventory

`full-suite.csv` lists the 1,936 test cases from `cargo +1.98.1 nextest list --locked --all-targets --message-format json` at `e5cf8edc50b094805b8495bbc57b8012949cfc00` (`main`, 2026-10-15). Outcomes and durations come from that exact revision's successful [CI quality run](https://github.com/zbarno/kool.ade/actions/runs/38814357914): 1,934 passed, 2 skipped, 0 failed. The nextest wall time was 219.890 seconds; the sum of per-case durations was 2,983.396 test-seconds and is cumulative worker time, not wall time. CI runs the suite with 16 nextest threads. The full test job, including setup and compilation, took 292.14 seconds.

Each row records the test ID, source location and mapping method, test-name intent label, category and dependency signals, duration, result, same-name overlap candidate, and current review decision. Source locations were matched by module path for 1,870 tests. The other 66 module-path fallbacks were checked against the Rust sources: each cited line is the unique declaration of that test function name in the repository. The inventory and generator now record that mapping explicitly. This verifies locations only; category, dependency, and intent values remain name/path signals, and invariant-level overlap review is still pending. The generated intent label is the test name, not a reviewed invariant description.

Four same-name test pairs remain and were reviewed. The two archive diagnostic cases exercise separate staging paths; the Cargo and npm cache cases exercise separate implementations. PR #215 removed two exact duplicate feature-approval test copies and kept their canonical counterparts. The removed copies summed to 23.141 test-seconds in the pre-consolidation #213 report. This current inventory does not contain those removed tests, and the available timing comparisons do not establish a full-suite wall-time reduction from their removal.

The remaining 1,930 rows have no exact test-name collision; semantic overlap review is pending. A lack of name collision does not establish uniqueness. Do not remove or consolidate a test from this inventory alone: compare its invariant and production boundary with existing coverage, then record the evidence and decision. The focused core long-tail profile is in [core-implementation-slowest.md](core-implementation-slowest.md); migration coverage outside that module is reviewed in [legacy-migrations-outside-implementation.md](legacy-migrations-outside-implementation.md).

To refresh the inventory, capture `cargo +1.98.1 nextest list --locked --all-targets --message-format json` and the JUnit artifact from a successful full-suite CI run at the same commit. Run `python3 scripts/generate-test-inventory.py --nextest-json <list.json> --junit <nextest.xml> --repo . --output docs/test-inventory/full-suite.csv`. The generator carries forward explicit review decisions for matching test IDs. Keep the exact source revision, workflow run URL, outcomes, and wall time together; do not compare different suite revisions as a before/after result.
