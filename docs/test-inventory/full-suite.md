`full-suite.csv` lists 3,622 tests for the current `feat/enforce-planning-repository` tree; the inventory was regenerated from this tree's Nextest listing and a successful full JUnit run taken on top of revision `3ec651f6` (immediately before the sibling-pair commit it documents), and prior source-review notes were preserved for matching tests. The full all-target run for that tree completed with 3,606 passed, 16 skipped, and 0 failed in 209.495 seconds; the sixteen skips are the Docker-dependent runtime-QA and publication cases. This tree enforces planning in a separate Git repository: connecting a code checkout without an associated managed planning repository is refused with an actionable setup error (refusals plant no state in the checkout), the planning-repository welcome card gains its own folder browser so shared planning checkouts can be selected anywhere on disk, managed-store bootstrapping and the explicit managed-workspace legacy migration flow keep their sanctioned readers of legacy layouts, MCP operator configuration lives in the operator-local planner state directory, context-free planning-store read failures surface the offending artifact path, and a new "start a new project" welcome track creates a visible sibling pair (`Parent/<name>` code repository + `Parent/<name>.packet` planning repository), seeds and associates the planning repository through the ordinary join path, and registers the code checkout before connecting through the standard gate.

Each row records the test ID, source location and mapping method, test-name intent label, category and dependency signals, duration, result, same-name overlap candidate, and review note. For the original #204 tree, source locations were matched by module path for 1,895 tests; the other 66 unique-function matches were checked against Rust sources. This verifies locations only; generated category, dependency, and intent values remain name/path signals. The nine appended issue-branch rows and the new main-branch provider-probe row have individual fixture and invariant notes and are included in this same-revision regeneration. The generated intent label is the test name, not a reviewed invariant description.

Four same-name pairs (eight test cases) remain and were reviewed. This current inventory does not contain those removed tests, and the available timing comparisons do not establish a full-suite wall-time reduction from their removal.
