# Full Rust test inventory

`full-suite.csv` indexes every Rust test discovered by `cargo-nextest list --locked --all-targets` at `7c69a90692769ccb0e81d2b8ac032da133ee1d82` (#213). Per-test durations and outcomes come from the matching successful [quality run](https://github.com/zbarno/kool.ade/actions/runs/38804158524), whose JUnit report recorded 1,936 passed and 2 skipped, with no failures. The nextest wall time was 227.729 seconds. The sum of case durations is 3,055.789 test-seconds; it is cumulative worker time, not wall time.

Each row includes the test ID, source location and mapping method, a short intent label taken from the test name, JUnit duration, CI outcome, and exact same-name overlap candidates. Four same-name pairs were flagged in this baseline. Both feature-approval pairs duplicated the same two test functions; this PR removes the copies under `approval_flow/compare/task_generation.rs` and retains the canonical tests in `approval_flow.rs`. Those removed cases sum to 23.141 cumulative test-seconds in the baseline report. The other two pairs were reviewed and retained: Docker archive staging has two distinct diagnostic functions and outputs, while Cargo and npm call separate cache initialization implementations. One local full-suite run before consolidation took 240.833 seconds (1,936 passed, 2 skipped); the run after took 244.933 seconds (1,934 passed, 2 skipped). These trials show no full-suite wall-time reduction, so the measured result is the removal of two redundant cases and 23.141 cumulative test-seconds; collect hosted comparable timing before claiming a wall-time gain. A same-name collision is a lead, not proof of duplication, and no collision is not proof of uniqueness. Category and dependency columns are name/path signals; they do not prove which resources a test actually uses. Confirm resource use in the listed source before changing test selection or execution requirements. The 66 rows marked `function-name fallback` require source verification. Skipped tests have a zero JUnit duration and are explicitly marked.

Unresolved rows remain pending focused overlap review. This inventory does not claim that all tests are unique or that every possible duplicate has been reviewed. Removal or consolidation requires an invariant-level comparison and evidence that the production behavior is already covered. The measured core-implementation long tail is separately documented in [the core timing profile](core-implementation-slowest.md), and migration coverage outside that module is reviewed in [the legacy migration inventory](legacy-migrations-outside-implementation.md).

CI runs `cargo +1.98.1 nextest run --locked --all-targets --no-fail-fast --test-threads 16` and uploads `target/nextest/default/nextest.xml` for 14 days. Join the files with `python3 scripts/generate-test-inventory.py --nextest-json <list.json> --junit <nextest.xml> --repo . --output docs/test-inventory/full-suite.csv`. The generator carries reviewed decisions forward for matching test IDs. Preserve the source revision, workflow run URL, test outcomes, and wall time together so future comparisons use an identified suite revision.
